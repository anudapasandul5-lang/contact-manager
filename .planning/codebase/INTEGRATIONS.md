# External Integrations

**Analysis Date:** 2026-03-30

## APIs & External Services

**Supabase:**
- Supabase (Cloud PostgreSQL + Auth) - Primary backend database and user authentication
  - SDK/Client: @supabase/supabase-js 2.99.2
  - Client config: `src/lib/supabase/client.ts` (browser-side singleton)
  - Server config: `src/lib/supabase/server.ts` (server-side with access token support)
  - Config loader: `src/lib/supabase/config.ts` (environment validation)

## Data Storage

**Databases:**
- PostgreSQL (Supabase)
  - Connection: Via `DATABASE_URL` env var (server-side only)
  - Client: Drizzle ORM 0.45.1
  - Schema: `src/lib/db/schema.ts` with tables:
    - `contacts` - Contact records with name, email, phone, role, type (enum: employee|vendor|service_provider), notes, bio
    - `companies` - Organization records with name, industry, color, is_owned flag
    - `projects` - Project records with name, status (enum: planning|active|completed), optional company_id FK
    - `contact_companies` - Many-to-many join table (contact_id, company_id) with cascade delete
    - `contact_projects` - Many-to-many join table (contact_id, project_id) with cascade delete
    - `person_relationships` - Relationship graph between contacts with strength (weak|warm|strong), evidence type, and metadata
    - `intro_requests` - Introduction request workflow with requester/connector/target contacts and status tracking
  - Migrations: Generated by drizzle-kit in `drizzle/migrations/`
  - Access pattern: Supabase REST API via @supabase/supabase-js

**File Storage:**
- Local filesystem only - No file uploads or profile photos (uses colored initials instead)

**Caching:**
- None configured - All queries go directly to Supabase

## Authentication & Identity

**Auth Provider:**
- Supabase Auth (custom implementation)
  - Implementation: Session-based auth via `src/lib/auth/session.ts`
  - Sign-in route: `src/app/api/auth/sign-in/route.ts` - Creates Supabase auth session
  - Sign-out route: `src/app/api/auth/sign-out/route.ts` - Destroys session
  - Request guard: `src/lib/auth/server-guards.ts` - Validates requests have active session
  - Session storage: HTTP cookies with secure flags
  - Single-user model: No multi-user support or role-based access control

## Environment Configuration

**Required env vars:**

Client-side (prefixed with `NEXT_PUBLIC_`):
- `NEXT_PUBLIC_SUPABASE_URL` - Supabase project URL (loaded in `src/lib/supabase/client.ts`)
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` - Supabase anonymous JWT key (loaded in `src/lib/supabase/client.ts`)

Server-side (in `.env.local`):
- `DATABASE_URL` - PostgreSQL connection string from Supabase (loaded in `drizzle.config.ts`)
- `SUPABASE_URL` - Fallback Supabase URL (optional, used if NEXT_PUBLIC version missing)
- `SUPABASE_ANON_KEY` - Fallback Supabase key (optional, used if NEXT_PUBLIC version missing)

**Secrets location:**
- `.env.local` file (git-ignored) - Contains Supabase credentials and database URL
- Client secrets visible in browser (safe: anon key only, not service key)
- Server secrets protected by Next.js server-side execution

## API Routes (Internal)

**Contacts Management:**
- `GET/POST/DELETE /api/contacts` - Bulk contact operations at `src/app/api/contacts/route.ts`
- `GET/PATCH/DELETE /api/contacts/[id]` - Individual contact operations

**Companies Management:**
- `GET/POST/DELETE /api/companies` - Bulk company operations
- `GET/PATCH/DELETE /api/companies/[id]` - Individual company operations

**Projects Management:**
- `GET/POST/DELETE /api/projects` - Bulk project operations
- `GET/PATCH/DELETE /api/projects/[id]` - Individual project operations

**Relationships (Graph):**
- `GET/POST /api/relationships` - Relationship graph operations
- `GET/PATCH/DELETE /api/relationships/[id]` - Individual relationship operations

**Introduction Requests:**
- `GET/POST /api/intro-requests` - Intro request workflow
- `GET/PATCH /api/intro-requests/[id]` - Individual request updates
- `GET /api/intro-path` - Calculate intro path between two contacts

**Network Data (Mind Map):**
- `GET /api/network` - Fetch all nodes and edges for visualization at `src/app/api/network/route.ts`
  - Calls `src/lib/supabase/network.ts` for aggregated contact/company/project data
  - Returns formatted data for React Flow at `src/components/mind-map/MindMapCanvas.tsx`

## Data Query Patterns

**Supabase REST Queries:**
- Nested select pattern: `contacts.select('*, contact_companies(companies(*)), contact_projects(projects(*))')`
- Used in `src/lib/supabase/network.ts` for fetching network data with related entities
- Drizzle ORM used for migrations and type safety, but Supabase REST API used for queries

**Authentication Flow:**
1. User signs in via `src/app/api/auth/sign-in/route.ts`
2. Session created with access token stored in HttpOnly cookie
3. Subsequent requests authenticated via `src/lib/auth/session.ts`
4. Access token passed to Supabase API if needed
